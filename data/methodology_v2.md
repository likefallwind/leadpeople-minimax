# 四层分层编码模型 v2 · 方法论文档

> **本版本定位**：v2 在 v1/v3 基础上，**强制要求每条能力都有可追溯的 L1 原子事实 ID 链 + URL 来源**。
> v1/v3 的问题：v1 把"事实"和"能力"混为一层；v3 抽象出 L1 能力但未强制要求 URL 证据。
> v2 的硬约束：**Web search 唯一权威**、**每条事实有 URL**、**能力由事实链支撑**、**冲突并列保留**、**不知道就标未证实**。

---

## 一、四层模型定义

### 1.1 L1 原子事实（Atomic Fact）——"他做了什么"

**定义**：可独立验证的具体行为、事件、产出、状态。锚定在具体事件上，带时间、地点、主体、来源 URL。每条 L1 事实 = 一行可读可查的"人 + 动作 + 对象 + 时间 + 证据 URL"。

**判别标准**（5 条）：
1. ✅ **可独立查证**：URL 可访问 + 第三方来源（非仅当事人博客）
2. ✅ **5W 完整**：Who(主体) / What(动作/产出) / When(时间) / Where(机构/地点) / Source(URL)
3. ✅ **动作性**：动词性短语（"发表论文"、"获得奖项"、"创办公司"、"辞职"）
4. ✅ **可证伪**：可以"是"或"不是"独立判断
5. ✅ **不抽象**：不含形容词评价（"重大"、"卓越"、"奠基性"—— 这些留给 L2）

**反例**（2-3 个）：
- ❌ "30 年学术坚守" → 抽象评价，应进 L2
- ❌ "深度学习之父" → 外界称号，不是事件
- ❌ "改变了 AI 方向" → 影响力评估，不是事件
- ❌ "提出 MapReduce" → 看似 L1，但"提出"是状态描述；应说"2004 年发表 MapReduce: Simplified Data Processing on Large Clusters 论文（OSDI 2004, https://...）"

**数据规模**：60 人 × 平均 15-20 条 = **900-1200 条 L1 原子事实**。

---

### 1.2 L2 原子能力（Atomic Ability）——"他具备的特质/能力/状态"

**定义**：从若干 L1 事实中抽象出的、可识别的能力 / 特质 / 认知风格 / 行为倾向。每条 L2 能力 = "某人 + 抽象能力描述 + 2-4 条 L1 事实 ID 链 + 强度（高/中/低）"。

**判别标准**（5 条）：
1. ✅ **可由 L1 事实链支撑**：必须列出 2-4 条 L1 事实 ID，禁止凭空
2. ✅ **抽象层级高于 L1**：是 L1 事件背后的"为什么能持续做"或"做到了什么"
3. ✅ **可与他人 L2 对比**：同类型能力可在不同人之间横向比较
4. ✅ **不重复 L1**：不能是 L1 事件的"复述"（如"发表反向传播论文"是 L1；"独立设计深度学习核心算法"是 L2）
5. ✅ **不混同 L3 主题**：不应该是"原创算法贡献"这种主题词（应进 L3）

**反例**（2-3 个）：
- ❌ "反向传播算法发明者" → 是 L1 事件复述，应进 L1
- ❌ "顶级 AI 研究者" → 评价性，不是能力
- ❌ "原创算法贡献" → 已是主题词，应进 L3
- ❌ 孤立 L2（无 L1 支撑）：必须删除或补 L1 链

**数据规模**：60 人 × 平均 8-12 条 = **480-720 条 L2 原子能力**。

**L1 ↔ L2 关系**：1 条 L2 能力由 ≥ 2 条 L1 事实支撑（可追溯到 L1）；1 条 L1 事实可支撑 1+ 条 L2 能力（如"2018 图灵奖"既支撑"原创算法能力"也支撑"顶级学术荣誉能力"）。

---

### 1.3 L3 二级能力簇（Secondary Cluster）——"能力的主题聚类"

**定义**：若干相似 L2 原子能力按主题聚类形成的更高阶主题。每个 L3 簇包含 5-30 条 L2 能力（来自不同人物的 L2 能力可聚类到同一 L3 簇）。

**判别标准**（5 条）：
1. ✅ **主题明确**：单一清晰主题（"深度学习核心算法"、"学界长期坚守"、"通用大模型创业"）
2. ✅ **横向可聚类**：≥ 3 个不同人物的 L2 能力归属（孤立 L2 簇 = 主题过细）
3. ✅ **主题不与 L4 重复**：不应该是"学术影响力"这种元维度
4. ✅ **每条 L2 归属唯一**：一条 L2 能力归属 1 个 L3 簇（不跨组），避免重复计数
5. ✅ **粒度适中**：建议 15-25 个 L3 簇（不是 82 个过细，也不是 5 个过粗）

**反例**（2-3 个）：
- ❌ "Hinton 专属簇"（仅 1-2 人）→ 粒度过细
- ❌ "能力很强"（跨多主题）→ 粒度过粗
- ❌ "学术影响力"（元维度）→ 应进 L4
- ❌ 把"反向传播算法"当 L3 → 是 L1 + L2"独立设计算法" + 自身不构成簇

**数据规模**：**15-25 个 L3 二级能力簇**（v1/v2 历史上有 82 个，过细；v2 修正到 15-25）。

**L2 ↔ L3 关系**：每条 L2 能力归属 1 个 L3 簇（不跨组）；每个 L3 簇包含来自多人的多条 L2 能力。

---

### 1.4 L4 核心维度（Core Dimension）——"8 个高阶能力维度"

**定义**：从 L3 簇聚合抽象出的高阶能力维度。固定为 **6-10 个核心维度**（v1/v2 定为 8 个 D1-D8）。每个 L4 维度对应 2-5 个 L3 簇。

**判别标准**（5 条）：
1. ✅ **互斥性强**：每个 L3 簇归属 1 个 L4 维度（允许"主归 + 辅归"，但主归唯一）
2. ✅ **MECE 性质**：所有 L3 簇都有归属维度，无遗漏
3. ✅ **抽象层级最高**：是 L3 主题的"上层类目"
4. ✅ **可操作**：每个维度可独立打分（0-3 分）
5. ✅ **稳定性**：不因新增人物而频繁调整（核心维度应在 5-10 年内稳定）

**8 个核心维度（D1-D8 固定）**：
- D1 原创算法贡献（R&D Originality）
- D2 系统工程能力（Systems Engineering）
- D3 学术机构地位（Academic Position）
- D4 创业/商业化能力（Entrepreneurship）
- D5 政策治理参与（Policy & Governance）
- D6 长期主义深度（Long-termism）
- D7 跨界整合能力（Cross-domain Integration）
- D8 公共影响力（Public Influence）

**反例**（2-3 个）：
- ❌ "个人魅力"（不可证伪 / 不可打分）→ 拒收
- ❌ "国籍" / "性别"（不是能力）→ 拒收
- ❌ 把"创业"和"商业化"拆成 2 维（违反 MECE）→ 合并为 D4
- ❌ 临时新增"AI for Science 维度"（破坏稳定性）→ 应归 D1 原创算法

**数据规模**：**6-10 个 L4 核心维度**（v1/v2 固定 8 个）。

## 二、抽取规范（Worker 操作手册）

### 2.1 L1 原子事实抽取规范

**最小操作单元**（5 要素）：
```
L1 编号（AF-{人物前缀}-{序号}）
事件描述（动词性短语）
时间（YYYY-MM-DD 或 YYYY 或 区间）
主体（人物 + 机构 + 合作者）
来源 URL（必须可访问）
```

**抽取步骤**：
1. 读人物事实卡（10 维度，1500-3000 字）
2. 对每条潜在事实，做 **Web search 验证**（至少 1 个独立第三方来源）
3. URL 失效 → 标"未证实"而非删除
4. 同一事件多个来源 → 选最权威的（官网 > Wikipedia > 个人主页 > 二手报道）
5. 写入 L1 文件时**每条标注**："事实卡原始内容 + Web 验证结果"

**质检规则**（worker 自检 + 交叉核验）：
- 每条 L1 必须有 URL；缺 URL = 不通过
- URL 失效但事实可能对 → 标"⚠️ 未证实（URL 失效）"
- 时间冲突 → 保留两个时间，标"待裁定"
- 与事实卡原文冲突 → 标"⚠️ 与原事实卡冲突，新搜索为准"

### 2.2 L2 原子能力抽取规范

**最小操作单元**（5 要素）：
```
L2 编号（AB-{人物前缀}-{序号}）
能力描述（"在 XXX 方面的能力/特质/状态"）
支撑 L1 列表（2-4 条 L1 编号）
强度（高/中/低）
归属 L3 簇（待定，第二轮回填）
```

**抽取步骤**：
1. 读完该人物 15-20 条 L1 事实
2. **聚类 L1**：把 2-4 条相关的 L1 归一组（"这些都是'算法贡献'类"）
3. **抽象为能力**：把 L1 聚类提升为"能力描述"（必须动词性 + 抽象名词，如"独立设计 XXX 的能力"）
4. **反向验证**：每条 L2 必须能用 1-2 句话从 L1 链推断
5. **强度标定**：
   - **高**：L1 链强 + 时间跨度大 + 多个机构/项目
   - **中**：L1 链清晰 + 但仅 1 个项目/机构
   - **低**：L1 链弱（仅 1-2 条事实）

**质检规则**：
- **L1 链必须 ≥ 2 条**，否则 L2 不通过
- **不能 L1 链全部来自同一时段**（暗示过度抽象）
- **不能 L1 链全部来自同一项目**（暗示是该 L1 的复述）
- **不能 L1 链全部来自第三方评价**（非一手事实）

### 2.3 L3 二级能力簇聚类规范

**聚类步骤**：
1. 把 60 人 × 8-12 条 L2 = ~600 条 L2 拉成二维表（人 × L2）
2. 计算 L2 之间的**主题相似度**（关键词 + 抽象层级）
3. 初始聚类 → 15-25 个 L3 簇
4. **簇内同质性检查**：簇内 L2 是否都"指向同一类主题"？
5. **簇间异质性检查**：不同 L3 簇之间是否"主题不重叠"？
6. 必要时拆 / 合（粒度调整）

**质检规则**：
- 每个 L3 簇 ≥ 3 个不同人的 L2 能力（避免个人专属簇）
- 每个 L3 簇 ≤ 30 条 L2 能力（避免巨型簇）
- 不允许"其他"兜底簇（必须归到具体主题）

### 2.4 L4 核心维度聚合规范

**聚合步骤**：
1. 把 15-25 个 L3 簇按"主归"映射到 6-10 个 L4 维度
2. **MECE 检查**：所有 L3 簇都映射了，映射无遗漏
3. **稳定性检查**：模拟新增 5 个新人物，是否仍归到现有 L4？
4. **可打分检查**：每个 L4 维度是否有清晰的 0-3 评分标准？
5. 必要时调整 L4 名称 / 数量（但需保留向后兼容）

## 四、与现有 82 个 L2 簇的对照表

> 现有 clusters.md 包含 82 个 L2 二级能力簇（v1/v2 阶段产物），本方法论 v2 修正到 15-25 个 L3 簇。
> 对照原则：粒度过细的应**合并**；粒度过粗的应**拆分**；与 L4 维度重复的应**下沉到 L3**；L2 簇之间有重叠的应**整合**。

| v1/v2 现有 L2 簇 | v2 建议处理 | 理由 |

## 五、冲突解决 SOP

### 5.1 Web 搜索结果之间的冲突

**场景**：搜索"Hinton 出生年份"出现 1947 / 1947.12.6 / 1947 年 12 月 6 日 三个版本

**SOP**：
1. 优先官方/权威来源（诺贝尔奖官网、剑桥校友录、多伦多大学官方 bio）> Wikipedia > 媒体
2. 时间精度统一到天（如 Wikipedia "6 December 1947"）
3. 同一事实多来源冲突 → 标"⚠️ 冲突待裁定"，并列保留 2 个时间
4. **不在 L1 中选边**（避免主观判断）
5. 例外：如出现明显事实错误（如把 Hinton 出生写成 1957）→ 标"⚠️ 来源疑似错误，已剔除"

### 5.2 原事实卡 vs Web 搜索结果冲突

**场景**：原 v1 事实卡说"周靖人 2000-2004 北大本科 + 2004-2009 清华博士"，但 web 搜索结果显示"中科大本科 + 哥伦比亚大学博士"

**SOP**（v2 关键修正）：
1. **Web 搜索结果为准**（v2 硬约束："Web search 唯一权威"）
2. **不删除原事实卡**，而是在 L1 文件中**并列保留 2 个版本**：
   - `L1 事实（v1 事实卡原文）：周靖人 2000-2004 北大本科`
   - `L1 事实（v2 web 验证）：周靖人 1999-2003 中科大本科（更可靠）`
3. **用 ⚠️ 标记冲突**：v1 vs v2 严重事实修订
4. **不在 L2 抽象中使用 v1 数据**：v2 的 L2 能力只能基于 v2 web 验证的 L1 链
5. **冲突解决责任在 worker**：worker 必须做 web 验证，不能照搬 v1 事实卡

### 5.3 L1 vs L2 抽象过度

**场景**：把"1987 年赴加" + "2001 年获多大最高头衔" + "2024 年获诺奖" → 抽象成"对神经网络有 30 年孤独坚持的定力"—— L2 抽象过头，**仅基于事实链推断不出"孤独定力"**

**SOP**：
1. L2 抽象必须**可由 L1 链直接推断**（"30 年坚持"可由 30 年 L1 链推断；"孤独定力"是 L1 链没有的额外评价）
2. 抽象过头 → 拆分或降级为 L1
3. 例："30 年学术坚守" ✅（L1 链：1987-2024 多伦多任期 + 30 年神经网络寒冬）
4. 反例："30 年孤独定力" ❌（"孤独"是 L1 链没体现的评价）

### 5.4 L2 vs L3 粒度混淆

**场景**：把"独立设计深度学习核心算法的能力"放 L3（实际是 L2），或把"AI 治理与安全"放 L2（实际是 L3）

**SOP**：
1. L2 应是"单能力描述"（一个人在某个方面的特质）
2. L3 应是"主题聚类"（跨多人的 L2 归一组）
3. 测试方法：能否列举 ≥ 3 个不同人物的 L2 归属该主题？是 → L3；否 → L2
4. 例："深度学习算法贡献" 是 L3（Bengio/Hinton/LeCun/He Kaiming/Ilya/Goodfellow 都有 L2 归属）
5. 反例："Hinton 30 年孤独定力"是 L2（仅 Hinton 一人有）

### 5.5 不知道就说不知道

**SOP**：
- 查不到 web 来源 → 标"⚠️ 未找到可信来源"
- 不允许"基于训练知识"瞎编
- 不允许"我猜是 1986 年"—— 必须 web 验证
- 不允许"时间对不上就剔除"—— 标"待裁定"保留

## 六、与原版最关键的 3 个差异（1 句话总结）

**v2 四层模型与 v1/v3 的 3 个核心差异**：**①严格事实/能力二分**（L1 = 事件 / L2 = 能力，不可混淆）；**②Web 唯一权威 + URL 强制**（每条 L1 必带 URL，缺源即"未证实"，v1/v3 无此约束）；**③L2 必带 L1 链**（≥ 2 条 L1 事实 ID 支撑，v3 的 L1 抽象可无证据）。
